> 配套《证据循环法》使用。术语取自 FDE 案例库原生表达，不含传统销售方法论词汇。每卡一页，站号对应五站。

## 卡 1 · 挑活检查单（第 1 站：这活值得做吗）

对候选工作流逐条打勾，任一 ✗ 就打住：

- [ ] 高量：量大到改进值得——量 = 每天流过的工作单元总数（件 / 次），不是员工人数；改进价值 ≈ 单次节省 × 发生次数
- [ ] 可切最小切片：存在 1 渠道 × 1 意图 × 1 唯一 system of record 的窄路径
- [ ] 对错可判：结果能被干净判定（余额匹配 / 工单闭环 / 合规通过），不是开放题
- [ ] 证据可测：真实用户跑在端到端路径上能量出采纳与业务数
- [ ] 值驻场级投入：问题大到值得 FDE 进场
- [ ] 不逼客户搬家：能建在现有系统上
- [ ] ROI 够：三类价值里至少一类的数字撑得起投入

陷阱自查：我是不是因为「手头有现成代码」才选的它？

## 卡 2 · 进门姿势卡（第 2 站：怎么进、用什么词）

- 产品化动作：5 天工作坊 / 免费诊断 / 流程设计工作坊——小合同小步入场
- 用词敏感：客户对「审计 / audit」过敏，说「流程设计工作坊 / design sprint」
- 试用再采购三件套：免费诊断 / 小合同、shadow mode 起步、里程碑付款
- 帮谁（共创者赢）：发起人赢政绩 / owner 赢立功 / 把关人赢不背锅 / 操作员赢被赋能；被替代岗位非共赢对象——不承诺减员、不参与去留，增值叙事进场
- 不搬家三原则：建在已有系统上 / 保留流程形状 / 信任大于构建

## 卡 3 · 一周诊断路线（第 2 站产出 operating map）

- 周一：拿只读权限 + 对内部 champion 的清单
- 周二：坐在操作员旁边看真实工作 2 小时（文档流程 ≠ 真实流程）
- 周三：访谈 IT 安全负责人与业务线（别绕开安全）
- 周四：画 operating map（含例外处理）+ 三类价值量化 + 不作为的财务成本
- 周五：分角色汇报 → 要 4 周时间窗 + 一台真系统 + 一个真操作员

纪律：读原始产物（工单、旧系统数据），不读汇报材料；给客户的话是「我发现」，不是「我建议」。

## 卡 4 · 窄路径 PoC 设计卡（第 3 站：4 周造铁证）

- 选型（只看证据可产性）：最高产出渠道 → 对错可判意图 → 该意图唯一 system of record
- 范围：1 × 1 × 1；时间盒：4 周；全程埋点
- 三个陷阱自查：是不是在抛光 demo？（后端假连接器 = 一眼毙掉）是不是开了平行路径？（两个半成品 < 一个铁证）选的是最容易的还是最能出证据的？
- 战术让步话术：「平台确实会来，但第 4 周先证明证据，扩展以此为前提」

## 卡 5 · eval 与安全过关卡（第 3 站双证：凭它进第 4 站）

- [ ] eval 黄金样本集（含边界与红队案例）
- [ ] 回归门禁（改动要过 eval 才放行，防静默回归）
- [ ] 书面安全立场（让安全团队逐条审）
- [ ] 审计轨迹内建（客户看得见 agent 每一步）
- [ ] 提权路径：shadow mode → 人工复核 → 生产
- [ ] 红线书面化：不越权动客户资产 / 不可逆动作人审 / 全可追溯

通过标准 = 安全 / 合规书面放行 + eval 报告，双证齐全才能谈扩张。

## 卡 6 · 采纳条款清单（第 4 站前置：签约时就把采纳锁死）

- [ ] 合同点名 day-2 owner = 该生意单元实际负责人（职位 + 姓名，非采购审批人、非一线操作员）
- [ ] 30 / 60 / 90 天启用计划（谁、何时、什么指标）
- [ ] 「无厂商在场跑通」验收演练日期
- [ ] 业务信号定义（哪个数动了算成）
- [ ] 责任口径 = eval 门禁 + SLA（白纸黑字）
- [ ] 人类最终决定边界（不可逆动作清单）写进权限与合同
- [ ] 里程碑付款 = 证据节点
- [ ] 客户同意成功后作参考案例

提醒：shipped ≠ adopted——合同签了只是拿到失败的开场机会。

## 卡 7 · 四类疑虑应答卡（当场出示证据物件）

| 疑虑 | 一句话应答 | 证据物件 |
|---|---|---|
| AI 幻觉 | 「我们只在对错可判、可回滚的步骤用模型」 | eval 集样本 + 失败案例分析 |
| 安全性 | 「模型不搬家；agent 留审计轨迹，shadow 起步逐步提权」 | 权限矩阵 + 审计轨迹 + 提权路径图 |
| 谁负责 | 「不可逆动作人类最终决定；责任 = 评估证据达标」 | 红线清单 + SLA 口径 |
| IT 被取代 | 「系统不动，它长出 AI 能力；交付证据上 owner 写的是你」 | 集成架构图 + 共建排期 |

## 卡 8 · 分角色汇报模板（技术语言 / 决策语言）

- 决策语言（给决策层，10 分钟）：痛（他的原话）→ 不作为成本 → 期望能力 → 证据（数字）→ 下一份证据的日期与成本 → 要什么（时间窗 / 人 / 系统）
- 技术语言（给技术干系人，10 分钟）：架构图 → 为什么 AI 属于这一段 → eval 设计 → 失败模式与回滚 → 审计轨迹与权限 → 埋点方案
- 金句：「第 30 天你没有头衔但你有证据」；每轮只承诺「下一份证据」，不承诺结果。

## 卡 9 · 术语对照卡（英文原词 → 大陆课堂说法）

| 英文原词 | 大陆课堂说法 | 一句话释义 |
|---|---|---|
| adoption / adopt | 用起来、真在用、落地使用 | 人 + 指标 + 30 天窗口；「上线」不算，「人在用」才算 |
| shipped ≠ adopted | 上线了 ≠ 在用了 | 反例：demo 完美、部署后 3 个月被悄悄关停 |
| three buckets of measurement | 三类价值：增收 / 降本 / 风控 | 决策层不认愿景，方案最后都要落进至少一类 |
| evals / evaluation | 评测、评测集 | 黄金样本跑出来的可复测成绩 |
| narrow path | 窄路径、最小完整切片 | 1 渠道 × 1 意图 × 1 系统，4 周打通的一条真路 |
| system of record | 唯一事实系统、主记录系统 | 业务数据唯一的权威落点；不写回它 = 等于不存在 |
| cost of doing nothing | 不做的代价、拖着的成本 | 诊断简报必写的一项，日后 ROI 叙事的基准线 |
| operating map | 真实流程图、现状地图 | 文档流程 ≠ 真实流程，得坐在操作员旁边撬出来 |
| shadow mode | 影子模式、旁路试跑 | 先只观察不干预，逐步提权到生产 |
| named day-2 owner | 该生意单元实际负责人 | 被改造工作流日常运营的主管 / 总监级个人 |
| bootcamp | 集训营、入场工作坊 | 拿客户数据做出可用用例，再谈钱 |
| de-risk / try before buy | 试用再采购 | 客户看见结果再决定采购 |

三处易错辨析：

1. 风险类说「风控」而非「控险」——大陆口头习惯说「风控」（风险控制）。
2. eval 不是缩写词——是 evaluation 的简称（AI / ML 行业黑话），不是首字母缩写。
3. owner 点名 ≠ 让客户签收付款——点名的是「被改造工作流的实际负责人」（主管 / 总监级），不是采购审批人，也不是一线操作员。
