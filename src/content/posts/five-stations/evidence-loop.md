> 提示：这不是「又一套销售漏斗」。它的形状是循环 + 证据成熟度门，不是「发现 → 赢」的直线。请先读第一节的三条公理，它们是全部设计的约束条件。

## 一、三条公理（方法论的约束条件）

**公理 1：智能在商品化，部署才是护城河。**
当几十个企业客户都在用同一个技术栈，智能本身不可能是护城河；优势转移到「在哪里、如何、为什么使用它」。推论：FDE 卖的不是模型、不是软件许可，是「在你这套系统里被真正用起来并产生业务结果」这种能力。一切动作都要回答这个问题，而不是回答「我的平台多好」。

**公理 2：试点默认失败，生意不靠 demo 靠采纳。**
有统计显示，生成式 AI 试点失败率高达 95%；有项目做到了 84% 的准确率，采纳率却只有 6%；也有 demo 做得完美、三个月后却被悄悄关停的案例。推论：演示成功、合同签署，在 FDE 生意里不构成任何意义的「赢」。唯一的成功单位是「采纳」：一个人 + 一个指标 + 一个 30 天窗口——该生意单元的实际负责人被点名、业务信号动了、操作员在没有工程师在场的情况下跑通新流程。

**公理 3：证据是唯一货币。**
决策层不认愿景，认三类可测价值（收入提升 / 风险降低 / 成本节省，大陆口头：增收 / 降本 / 风控）和可复测的证据（eval 数字、埋点、采纳指标）。「证据打败管道」「读项目的原始产物，不读它的汇报材料」「looks fine 是全行业最贵的两个词」。推论：每一次面向客户的说服，都必须携带一个当场可查的证据物件；任何无法用证据回答的问题，正确动作是「去做个实验」，而不是「给个承诺」。

## 二、生意单元与生意公式（卖什么、按什么单位算钱）

- **生意单元 = 一条被证明并被采纳的工作流**（一个诊断对象 + 一个窄路径 + 一套 eval + 一个被点名的 owner）。Palantir 的扩张方式正是「价值被证明后，用例、工作流、数据域逐层叠加」——它以「被证明的工作流」为单位生长，不以「客户数量 / 许可数」为单位。
- **生意公式**：收入 ≈ 已采纳生意单元数 × 单单元价值 × 复用杠杆（模板在同行业第 2、3 家客户复用后摊薄交付成本）。
- **两阶段收入形态**（如实呈现，不自欺）：
  - 服务态（起步 / 单客定制）：诊断免费或低价进门 → 价值证明后诊断收费 + 实施月费 / 一次性费；毛利率低、靠人。
  - 平台态（终局）：多年期、结果对齐的固定费用合同，收入随时间向订阅倾斜。
  - 一个必须内建的警告：别假装自己是 SaaS——如果模式本质是驻场服务 + 平台，就按它的毛利结构诚实经营。

## 三、主循环：五站证据成熟度模型

```
第1站 挑活 ──► 第2站 进门与诊断 ──► 第3站 证明 ──► 第4站 采纳 ──► 第5站 扩张与复制
(这活值得     (真痛点/真系统/      (能work且       (人在用+        (叠加用例/
 做吗)        不作为成本)          安全能过审)     业务信号在动)   模板复制/订阅化)
   ▲            ▲                ▲              │
   └── 弹回：诊断发现→换活；证明失败→重做窄路径；采纳失败→回诊断或放弃
```

**关键性质（与一切直线漏斗的本质区别）**：

1. 非线性：采纳阶段的发现把你弹回诊断，评估阶段的发现把你弹回原型。
2. 重心在「签约之后」：合同签署只是第 3 站到第 4 站之间的一张纸，生意的生死线是第 4 站（采纳）。
3. 能力在销售过程中被现发现：在第 2-3 站之前，卖方自己也不知道 agent 在这家组织能不能成立——所以不存在「先承诺后交付」，只存在「先证明后放大」。
4. 一个客户 = 一组处于不同站位的生意单元，不是「一个商机」。

### 第 1 站 · 挑活：选择值得被诊断的工作流

选择标准（冷酷版）——只看「能否产出清晰证据」，不看战略重要性、不看潜在收入：

- **高量**：流程量大到改进值得。量 = 单位时间内流过该流程的工作单元总量（每天处理的件 / 次数），不是使用它的员工人数；改进价值 ≈ 单次节省 × 发生次数。
- **可切窄路径**：存在「1 渠道 × 1 意图 × 1 唯一 system of record」的最小切片。
- **对错可判**：该步骤的结果能被干净判定，不硬套 if-else 能解决的事。
- **证据可测**：真实用户跑在端到端路径上才量得出采纳与收入。

不接的活：低量或 ROI 不够的流程（10 步流程可能只有 3 步值得 AI）；需要客户「搬家」的活（客户花两年几百万建的系统是资产，不是障碍）。

### 第 2 站 · 进门与诊断：免费或低价制造「真痛点地图」

- 进门姿势：小合同小步入场（5 天工作坊、免费诊断）。用词敏感：客户对「审计 / audit」过敏，叫「流程设计工作坊 / design sprint」效果更好。
- 诊断产出物：真实工作流（含例外处理——文档流程 ≠ 真实流程，真实玩法只在一个人的脑子里，必须坐在那个人旁边一点点撬出来）；三类价值量化 + 不作为的财务成本；确定唯一 system of record。
- 给客户的话是「我发现」，不是「我建议」——读原始产物（工单、旧系统数据），不读汇报材料。
- 不搬家三原则：建在已有系统上、保留流程形状、信任大于构建。
- 本站的门票：客户认可「痛是真的 + 不作为成本成立」，并给你一台真系统、一个真操作员和一个 4 周时间窗。

### 第 3 站 · 证明：窄路径 PoC + eval，把非确定性变成证据

- 窄路径：1 渠道 × 1 意图 × 1 system of record 的最小端到端切片，4 周 timebox。
- 三个原型陷阱：选最容易的路径；demo 抛光（界面完美但后端是假连接器）；平行路径（两条对冲 = 两个半成品）。
- eval 与安全过关：黄金样本 eval 集、红队攻击测试、书面安全立场；审计轨迹内建——不能让客户看不见 agent 在干嘛；shadow mode → 逐步提权到 production，不搞大迁移。
- 红线（责任边界，本站就要书面化）：不越权动客户资产、不可逆动作保留人审、一切可追溯。
- 本站的门票：eval 报告 + 安全 / 合规放行，双证齐全。

### 第 4 站 · 采纳：让「人在用」真实发生（生意的生死线）

- 采纳三条件（可考核验收）：被点名的 day-2 owner（该生意单元的实际负责人，职位 + 姓名写入合同）；动了的可度量业务信号；操作员在没有工程师在场的情况下跑通整个新工作流。
- 30 / 60 / 90 天启用计划 + 超级用户深度培训；把「采纳」当终点而非 checkbox——混淆「部署」与「采纳」是 FDE 生意最贵的错误。
- 读动词不读名词：跟进时看原始产物（日志、埋点、commit），不看汇报材料。
- 失败即诚实：采纳失败触发「回到诊断或放弃」，不硬撑。
- 本站的门票：30 天内出现「无厂商在场也在用」的事实 + 一个可对外引用的采纳证据包。

### 第 5 站 · 扩张与复制：从一条工作流到一份生意

- 客户内扩张：已证明的工作流 / 部门 / 数据域逐层叠加；每个新用例是一个新的生意单元，从第 1 站重新走。
- 收入形态演进：多年期结果对齐合同、固定费、向订阅倾斜；每个成功采纳自动成为下一个商机的开场证据。
- 跨客户复制：第 1 家跑出的范式被抽取成模板；第 2、3 家同行业客户验证可复用后，才谈行业规模化——在此之前不要用「行业平台」的叙事去谈任何客户。
- 增长的真实约束：不是销售线索，是人力供给与模板化速度。扩张节奏必须跟这两条供给线对齐。

## 四、贯穿五站的四个业务动作

1. **三类价值收口**：所有对外沟通都收到「收入提升 / 风险降低 / 成本节省」三类上（增收 / 降本 / 风控）。
2. **分角色沟通**：同一方案按听众角色排练两种讲法——技术语言（架构与决策）给技术干系人，决策语言（问题 / 结果 / 证据 / 风险）给决策层。
3. **试用再采购是销售动作，不是谈判筹码**：免费诊断、小合同、shadow mode、里程碑付款都是它的落地形态——每一步都是「让对方不用赌」的设计。
4. **信任建设 = 让共创者赢**：发起人赢政绩、把关人赢不背锅、owner 赢立功、操作员赢被赋能。被替代的岗位不是共赢对象——不承诺减员、不参与客户去留决策，用增值叙事进场。

## 五、两条规模化路径

| 决策变量 | 路径 A：大客户工作流叠加 | 路径 B：行业模板规模化复制 |
|---|---|---|
| 生意单元来源 | 同一客户的用例逐层叠加 | 同行业不同客户的同类工作流 |
| 收入形态 | 高 ACV 集中、多年期结果合同 | 中低 ACV 起量、靠复用摊薄成本 |
| 供给瓶颈 | 人力（能同时驻场几个客户） | 范式抽取与模板化速度 |
| 适用问题 | 高价值 / 高风险 / 高定制 | 同构高频流程（客服 / 财务 / 合规 / 运维） |
| 起步证据 | 1 个客户的 1 条铁证工作流 | 同行业第 2-3 家验证「模板可复用」 |

两条路径共用同一条证据循环，区别只在「生意单元从哪来、收入向哪倾斜」。

## 六、生意健康指标（替代传统管道 / 赢率管理）

| 指标 | 含义 | 证据物件 |
|---|---|---|
| 采纳率 | 进入第 4 站后 30 天真在用的比例 | 埋点 / 无厂商在场记录 |
| 叠加速度 | 单客户单位时间内新开生意单元数 | 新单元诊断报告数 |
| 复用率 | 模板被第 N 家客户使用的次数 | 范式库 |
| 证据放行数 | 通过安全 / 合规审查的第 3 站产物 | 书面放行书 |
| 收入结构 | 服务费 vs 订阅 / 结果费占比 | 合同台账 |
| 止损数 | 主动放弃的单元数（越多越健康） | Go / No-Go 记录 |

## 七、诚实的局限

1. 归纳基础有限：公开的一手「销售过程」案例稀缺，本模型主要归纳自一线 FDE 访谈与公开信息，行业语境需要用真实项目校准。
2. outcome 定价与责任条款的行业成熟度不足：红线是原则，写入合同的具体责任边界尚无足够公开判例。
3. 它回答「怎么把一个生意单元做活并滚起来」，不回答「从零到第一个客户的钱从哪来」。
4. 它刻意不用传统销售漏斗的「赢率 / 阶段」语言，因为 FDE 生意的死亡大多发生在「签约之后」；如果你的组织习惯用漏斗管理，可以映射回去，但要知道重心在第 4 站。
